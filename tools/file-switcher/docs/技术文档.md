# 文件版本切换器 · 技术文档

需求与验收标准见 [需求文档.md](需求文档.md)。本文档说明实现结构、协议契约与维护方式。

## 1. 整体结构

```
folder_app.py            入口，仅 40 行；PyInstaller 的入口路径保持不变
fsx/                     实现包
  paths.py               资源根与数据根（冻结时为 _MEIPASS）
  errors.py              错误码 → 通俗中文 + 下一步
  backend.py             调用 folder-switcher.ps1、校验返回契约
  store.py               读写配置的唯一入口（薄封装 profile_store）
  model.py               只读视图：按 id 查找，取代标签反解析
  ui/
    app.py               主窗口：视图切换、后端编排、结果分发
    home.py              简单首页
    advanced.py          高级管理（五个标签页）
    wizard.py            三步建版本向导
    dialogs.py           弹窗唯一出口，杜绝英文原文裸奔
    theme.py             配色与 DPI 缩放
folder-switcher.ps1      后端：真正读写文件、事务、回滚
profile_store.py         配置校验与原子写入
docs/                    本文档与需求文档
tests/                   55 个用例
```

### 两条硬约束

1. **资源读取必须经 `fsx.paths`**。冻结后资源在一次性临时目录（`sys._MEIPASS`），
   任何"往脚本同目录写文件"的写法在打包版都会失败。
2. **弹窗必须经 `fsx.ui.dialogs`**。`tests/test_units.py::ErrorTranslationTests`
   会断言这一点：后端英文原文永远不进入主要提示。

### 分层原因

旧版本把 Tk 根窗口、内存配置、ps1 参数拼装、JSON 协议解析和全部弹窗塞在一个 973 行的类里，
其中 `handle()` 是所有耦合的汇聚点。现在的对应关系：

| 职责 | 现在的位置 |
|---|---|
| 路径 | `paths` |
| 进程调用与协议校验 | `backend` |
| 配置读写 | `store` |
| 按 id 查找 | `model` |
| 交互与编排 | `ui.app` + 各视图 |

已删除的历史包袱：`_FallbackStore`（与 `ProfileStore` 校验强度不同）、
`_pending_action`、`_using_fallback_store`、`runner._process`、`open_legacy`，
以及全部 v1 代码（`gui/`、`switch-files.ps1`、`switch-*.cmd`、`config.json`）。

## 2. 后端协议契约

`folder-switcher.ps1` 把结果写到 stdout，**单行 JSON**：

```jsonc
{
  "schemaVersion": 2,
  "ok": true,
  "action": "status",
  "data": { /* 依 action 而异 */ },
  "error": { "code": "...", "message": "..." },  // ok 为 true 时是 null
  "transaction": { "id": "...", "status": "...", "path": "..." }  // 仅 apply/rollback
}
```

退出码约定：`ok:true` → 0，`ok:false` → 1。
`backend.parse_result` 会拒绝自相矛盾的返回（成功标记与退出码不一致时不采用）。

### 各 action 的 data

| action | data 关键字段 |
|---|---|
| `Status` | `currentMode`（版本 id 或 `unknown`/`ambiguous`）、`states[]`（含 `exact`、`fileCount`、失败时 `error`）、`managedCount`、`unmanagedCount`、`blockedProcesses[]` |
| `Scan` | `files[]`（`path`/`size`/`sha256`）、`managedCount`、`unmanagedCount` |
| `Capture` | `fileCount`、`missingCount`、`snapshotRoot` |
| `Diff` | `changes[]`、`counts{add,modify,remove,unchanged}`、`blockers[]`、`planDigest` |
| `Apply` | `changedCount`、`planDigest` + `transaction` |
| `Rollback` | `status: rolled-back`、`restoredCount` + `transaction` |

### 错误码表

`error.code` 是**稳定契约**；GUI 的行为完全由它决定，不做英文字符串匹配。
`error.message` 保留英文原文，只进日志与弹窗的"详细信息"。新增错误码时必须同步三处：
`folder-switcher.ps1`、`fsx/errors.py`、本表，并由 `tests/test_backend_contract.py` 与
`tests/test_units.py::ErrorTranslationTests` 双向校验。

| code | 触发条件 | 界面提示（下一步） |
|---|---|---|
| `guard-process-running` | 目标程序正在运行 | 关闭占用的程序后重试 |
| `operation-running` | 已有操作在进行 | 等当前操作结束 |
| `transaction-incomplete` | 存在未完成事务 | 到历史记录里撤销那次切换 |
| `state-not-captured` | 版本没有已保存内容 | 先保存一次当前内容 |
| `manifest-not-found` / `manifest-coverage` / `manifest-hash` / `manifest-size` / `manifest-identity` / `manifest-managed-mismatch` / `manifest-path-duplicate` | 存档缺失或与配置不符 | 重新保存该版本 |
| `profile-not-found` / `state-not-found` / `state-id-required` | 选中的设置或版本不存在 | 重新加载后重选 |
| `config-not-found` / `config-empty` / `config-schema` / `config-profile-id` / `config-state-id` / `config-default-profile` | 配置缺失或格式错误 | 重新设置 |
| `config-target-overlap` / `config-target-drive-root` / `config-target-system-root` / `config-targets-overlap` | 目标目录选择不当 | 换一个目录 |
| `config-managed-duplicate` / `config-managed-directory` / `config-cache-outside-target` / `config-snapshot-outside-state` / `snapshot-outside-state` | 配置内容非法 | 在高级管理里修正 |
| `source-inside-state` / `source-path-directory` | 保存来源不合法 | 选择真正的目录 |
| `path-unsafe-relative` / `path-reserved` / `path-device` / `path-reparse` / `path-not-found` / `path-empty` / `target-not-regular-file` | 路径不安全或不存在 | 检查路径 |
| `plan-target-conflict` | 目标内容不属于任何已知版本 | 看差异；确认可丢弃后允许覆盖 |
| `plan-delete-unauthorized` | 切换会删除文件 | 确认后允许删除 |
| `plan-delete-unrecognized` | 待删内容未被任何版本记录 | 先保存当前内容；`-AllowUnknown` 无法解除此拦截 |
| `plan-blocked` | 计划被安全校验拦住 | 按阻止原因处理 |
| `plan-stale-digest` | 预览之后文件又被改动 | 重新生成预览 |
| `plan-path-escape` | 受管路径逃出目标目录 | 移除该路径 |
| `digest-required` | Apply 缺少计划指纹 | 先生成预览 |
| `snapshot-hash-mismatch` / `staged-hash-mismatch` | 存档或暂存内容校验失败 | 重新保存该版本 |
| `backup-missing` / `backup-hash-mismatch` / `rollback-guard` | 备份缺失或目标已被改动 | 不要继续撤销，手动检查 |
| `transaction-id-invalid` / `transaction-not-found` / `transaction-already-rolled-back` | 撤销目标无效 | 刷新记录列表 |
| `value-not-boolean` | 配置布尔字段非法 | 修正配置 |
| `backend-no-output` / `backend-bad-json` / `backend-contract` / `backend-exit-mismatch` / `backend-timeout` / `backend-start-failed` | 传输层问题（由 `fsx.backend` 产生，不经 ps1） | 重试或确认版本一致 |
| `operation-failed` | 兜底 | 查看详细信息 |

`target-conflict` / `delete-not-authorized` / `delete-hash-unrecognized`
这三种 `blockers` 的具体条目仍出现在 `data.blockers` 里，`ui.app.plan_code_for()`
负责把它们映射成上表的 code。

### 三个曾经的真实缺陷（回归测试已覆盖）

1. **重复报错**：`Fail` 曾把 `$Message` 与 `$_.Exception.Message` 用 ` | ` 拼接，
   而调用方传入的正是同一个异常，导致字符串异常一律打印两遍
   （例如 `Guard process is running. | Guard process is running.`）。现在 `Fail` 只输出一份。

2. **开关参数恒为真**：`To-Bool` 未处理 `[switch]`。`SwitchParameter` 对象本身总是真值，
   于是 `-AllowUnknown` 在**没写**的时候也被当成"允许"，Diff 从不报告 target-conflict。
   现在 `To-Bool` 先判断 `[switch]` 再取 `.IsPresent`。

3. **BOM 让配置读不回来**：`Capture` 会用 PowerShell 的 `Set-Content -Encoding UTF8` 回写配置，
   该编码会写入 BOM，而 `profile_store` 用纯 `utf-8` 解码 → 保存成功但下次启动读不到。
   现在统一经 `Write-Utf8`（`UTF8Encoding($false)`）写出。

## 3. 数据与隐私边界

| 内容 | 位置 |
|---|---|
| 程序资源（ps1、模板） | 只读，随程序；冻结时在 `_MEIPASS` |
| 配置、版本内容、备份、日志 | `%LOCALAPPDATA%\AnyTestTools\FolderSwitcher` |
| 覆盖数据根 | 环境变量 `ANYTESTTOOLS_DATA_ROOT` |

仓库不得出现真实目标路径、快照内容、日志。`.gitignore` 已排除
`folder-data/`、`snapshots/`、`config.json`、`folder-config.json`、`*.bak`、
`build/`，以及 `dist/` 下除 `FolderSwitcher.exe` 之外的全部构建产物。

## 4. 打包

`FolderSwitcher-onefile.spec`：

- `datas` 必须包含 `fsx` 包与 `templates/`，`hiddenimports` 逐条列出 `fsx.*` ——
  否则冻结后 import 失败。
- `console=False`，输出的单个 `FolderSwitcher.exe` 双击即用。
- 打包后必须确认：数据写入 LocalAppData，**exe 所在目录没有新增任何文件**。

## 5. 测试策略

```
tests/e2e_harness.py             真实后端 + 临时目录 + 同步 runner 的公共夹具
tests/test_e2e_app.py           17 例  端到端：向导、切换、撤销、采集、扫描、确认不外泄
tests/test_backend_contract.py   9 例  每个错误码、回滚、删除两道路闸、BOM 回归
tests/test_folder_backend.py     8 例  后端全链路（真实 PowerShell）
tests/test_units.py             24 例  错误翻译、协议校验、命令拼装、配置查找
tests/test_docs_agreement.py     5 例  脚本/映射表/文档三处错误码一致
tests/test_profile_store.py      8 例  配置校验与原子写入
```

测试策略：**跨后端与文件系统的行为一律用端到端测试**，真实运行
`folder-switcher.ps1`、真实临时目录、真实窗口，只把会阻塞的对话框换成记录器。
纯逻辑（翻译表、协议校验、查找）用普通单元测试，不引入假后端——
假后端一旦与真实行为不一致，测试就会以"模拟漂移"的假失败掩盖真问题。

约定：

- 端到端测试全部在临时目录内，从不碰真实安装目录。
- 用 `-ExecutionPolicy RemoteSigned`（Windows 默认允许本地脚本），不使用 `Bypass`。
- 断言落在**磁盘上的文件内容**，而不是"调用了哪些函数"。

## 6. 维护约定

- 新增错误码：改 ps1 → 加 `fsx/errors.py` 条目 → 更新本表 → 加一条契约测试。
- 新增界面文案：不得引入需求文档 §7 对照表左侧的词汇。
- 界面尺寸：一律经 `Theme.scale()`，不要写死像素。
- 危险动作：先 `dialogs.confirm(...)` 说明影响范围，再调用后端。
- 提交前跑 `python -m unittest discover -s tests -t tests`，当前应为 **72 例全绿**。
