# 文件版本切换器 · 需求文档

本文档说明这个工具**为谁做、要解决什么问题、做到什么程度算合格**。
技术实现见 [技术文档.md](技术文档.md)。

## 1. 目标用户与场景

**主要用户**：非技术岗的测试、策划、美术，需要在同一台机器上让某个目录在一组文件版本之间来回切换。

他们**不知道**也不会关心：哈希、事务、快照、清单、差异、回滚这些概念。
他们只会说"切回正式版""换成测试版"。

**典型背景**：某个程序（游戏、工具）依赖目录里的若干文件；
不同测试场景需要不同版本的文件，手动复制粘贴容易漏、容易错，也容易覆盖不该动的东西。

**不面向**：需要跨机器同步版本、需要多人权限管理、需要定时自动切换的场景。

## 2. 核心场景

按优先级排列。前三个是必须一次点通的场景。

### S1 首次使用

用户第一次打开程序，不知道任何术语。

- 系统引导建立第一个版本：选文件夹 → 勾选文件 → 起名字并保存内容。
- 全程不需要用户理解"配置""清单""快照"这些词。
- 向导中途取消，不能留下半成品配置。

**验收**：一个没看说明的人，5 分钟内能完成第一次切换。

### S2 日常切换

用户已经设好两三个版本，每天来回切。

- 打开程序 → 看到当前是哪个版本 → 点目标版本 → 确认 → 完成。
- 操作步数上限：**1 次点击 + 1 次确认**。

**验收**：从打开到切换完成，只需要两次鼠标交互（含确认）。

### S3 切换受阻

目标文件被别的程序改动过，或正被占用。

- 必须用中文说清"发生了什么"和"下一步做什么"。
- 不能出现英文原文、错误码、堆栈信息作为主要提示。
- 要能一键查看是哪些文件有问题。

**验收**：故意改动目标文件后切换，提示能让人自己决定怎么处理。

### S4 后悔了

切错了，或想回到切换前。

- 首页提供"撤销上一次切换"。
- 说过"会改什么、不会改什么"之后才执行。

### S5 高级使用

用户想自己精细控制。

- 仍可管理多套目标设置、逐个勾选文件、查看比较明细、查看历史记录。
- 高级功能不得影响简单模式的可用性。

## 3. 功能需求

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-1 | 简单首页为默认视图 | 当前版本、各版本大按钮、设置入口、高级入口、撤销入口 |
| FR-2 | 三步建版本向导 | 选择文件夹 → 勾选文件 → 起名字 + 选内容来源 |
| FR-3 | 切换默认安全 | 先算差异再写入，写入前校验计划未被篡改 |
| FR-4 | 未勾选文件永不被触碰 | 这是本工具最核心的承诺 |
| FR-5 | 失败信息说人话 | 中文说明 + 下一步操作；技术细节折叠在"详细信息"里 |
| FR-6 | 危险动作二次确认 | 确认文案必须说明会改什么、不会改什么 |
| FR-7 | 版本名用户自定义 | 不预置任何名称 |
| FR-8 | 高级模式保留全部能力 | 多设置、文件管理、差异、历史、撤销 |
| FR-9 | 界面上不出现技术术语 | 简单模式下不得出现 digest / SHA-256 / schemaVersion / manifest / 受管 / 纳管 / 快照 / 采集 |
| FR-10 | 撤销上一次切换 | 首页一键回到切换前状态 |

## 4. 非功能需求

| 编号 | 需求 |
|---|---|
| NFR-1 | 首次成功切换 ≤ 5 分钟，无需阅读文档 |
| NFR-2 | 主流程 ≤ 2 次点击 + 1 次确认 |
| NFR-3 | 任何写操作要么完整成功、要么完整回退，不能留下半改状态 |
| NFR-4 | 用户数据只写在 `%LOCALAPPDATA%\AnyTestTools\FolderSwitcher`，可用 `ANYTESTTOOLS_DATA_ROOT` 覆盖；仓库内不得出现真实路径、快照、日志 |
| NFR-5 | 单个 exe 双击即用，无需预装 Python 或配置 PowerShell |
| NFR-6 | 在 100% / 150% 显示缩放下布局不截断 |
| NFR-7 | 程序不联网 |

## 5. 明确不做

- 不做云端同步或账号体系。
- 不做多用户权限管理。
- 不做定时/自动切换。
- 不重写后端文件操作逻辑（已由测试验证，重写风险大于收益）。

## 6. 验收标准

全部为**可执行**的检查，对应到自动化测试或人工确认。

| 编号 | 验收方式 |
|---|---|
| A-1 | 端到端：一次点击 + 确认后，勾选的文件内容变成目标版本，**未勾选文件字节不变** |
| A-2 | 端到端：空配置启动 → 走完向导 → 首页出现两个自定义名字的按钮 → 切换成功 |
| A-3 | 端到端：切换后点"撤销上一次切换"，文件恢复成切换前内容 |
| A-4 | 每个错误码都有非空中文说明，且说明中不含 digest / SHA-256 / schemaVersion / manifest |
| A-5 | 每个错误码都能由后端真实触发（契约测试逐条断言） |
| A-6 | 后端返回 `ok:false` 时，弹窗正文不含英文原文（原文只出现在"详细信息"里） |
| A-7 | 打包后的 exe 双击打开即为简单首页；数据写入 LocalAppData 而非 exe 所在目录 |
| A-8 | 仓库扫描：不含本机绝对路径（用户名目录、具体安装位置）、真实版本名与快照内容 |
| A-9 | 人工：由一个不了解该工具的人走一遍 S1 与 S2，确认无需帮助即可完成 |

## 7. 术语对照

界面上不再出现左侧词汇；保留此表供开发与文档统一口径。

| 技术词汇 | 界面上怎么说 |
|---|---|
| profile | 目标设置 |
| state | 版本 |
| capture | 保存版本内容 |
| snapshot | 已保存的版本内容 |
| managed file | 会一起切换的文件 |
| unmanaged file | 其它文件 |
| diff | 看看会改哪些文件 |
| apply | 切换到所选版本 |
| transaction | 记录 |
| rollback | 撤销这次切换 |
| digest | 计划指纹（仅高级模式显示） |
| manifest | （不展示） |
