# 文件夹状态切换器

这是独立于旧版 `switch-files.ps1` 的目录方案工具，入口为 `run-folder.cmd`。

## 核心概念

- **方案（Profile）**：一个目标文件夹和它的受管文件集合；以后可添加多个不同目标文件夹。
- **状态（State）**：一个受管文件集合的快照，例如开发、测试、自动化、发布。状态快照统一保存在配置文件父目录下的 `folder-data\snapshots\<profileId>\<stateId>\<采集版本>`。
- **受管文件**：明确加入方案的文件或目录展开出来的文件。
- **未管理文件**：目标目录中没有加入方案的文件。默认只统计和展示，永远不会被自动删除、覆盖或移动。

选择目录并不等于允许清空目录。目录扫描结果必须明确纳入受管集合后，才会参与状态切换。

## 启动

双击：

```text
run-folder.cmd
```

或：

```powershell
& "$env:LOCALAPPDATA\Programs\Python\Python310\python.exe" .\folder_app.py
```

## 当前版本支持

- 首次设置向导：选择目标目录、扫描候选文件并多选纳管，填写至少两个状态名和可选来源目录；取消不写盘，完成只写 Profile/State 元数据并引导采集；已有合法 Cocos 配置不会自动弹出向导；
- 首页用人话显示目标目录、当前状态、受管与未管理数量，状态列表提供预览、应用、去采集；扫描/Profile/JSON/事务仍在高级页；
- 查看 Profile 和状态快照是否匹配；
- 扫描受管文件数与未管理文件数；
- 计算状态差异；
- Dry-run 预览；
- 从当前目录或样例目录采集受管文件快照；
- 应用状态时只修改受管清单内的文件；
- 任意文件扩展名和二进制文件；
- 中文路径和带空格路径。

## 当前安全边界

- 默认不删除文件、不清空目录、不移动未管理文件；
- 不自动递归纳管目录外文件；
- 拒绝符号链接、junction 和其他 reparse point；
- PowerShell 脚本是唯一执行目标文件写入、快照写入和事务备份的位置；
- 切换前应关闭会占用目标目录的编辑器或游戏进程；
- 先使用“差异与切换”中的“仅预览，不修改文件”；应用按钮会强制重新生成 Diff，只有 digest 计划确认后才会写入；
- 快照缺失或受管清单发生变化时，应用会禁用/阻止并提示“去采集”；旧快照不会被清空；
- 真实应用前会创建 `folder-data\transactions` 事务目录。

## 配置

配置文件是 `folder-config.json`。可以复制 `profiles` 增加独立目标目录和状态，但必须为每个受管文件准备每个状态的快照。当前 Cocos 示例仍由旧版 `config.json` 管理，未自动递归升级真实引擎目录。

快照目录结构（由后端自动维护版本目录）：

```text
folder-data/snapshots/<profileId>/<stateId>/<capture-id>/
  manifest.json
  <受管文件相对路径>
```

GUI 与 runner 每次都显式传入相同的 `StateRoot=config父目录/folder-data`，避免相对 `snapshotRoot` 被解析到错误工作目录。

如需管理新的目录：

1. 在 `folder-config.json` 增加 Profile；
2. 将 `managed` 中的路径限定在 `targetRoot` 下；
3. 为每个状态设置 `snapshotRoot`；
4. 使用 GUI 的“采集状态”建立快照；
5. 先扫描、查看差异并 Dry-run，再取消预览选项执行。

目录切换仍是“显式受管集合的状态切换”，不是无条件镜像或清空整个文件夹。受管文件删除和受管缺失自动补建暂不作为默认能力开放。
